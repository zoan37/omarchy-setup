# Cyberspace: custom space/cyberpunk theme

A custom Omarchy theme — neutral near-black/gray backgrounds and gray text,
neon cyan accent (`#00e5ff`), hot magenta (`#ff4fd8`), with NASA/ESA/ESO space
photography plus one procedurally generated synthwave wallpaper. Built August
2026 on the XPS 13. (Originally used space-navy backgrounds and lavender text;
retuned to neutral grays Tokyo-Night-style because the blue tint was
overpowering in the terminal — the neon ANSI palette carries the identity.)

Theme files and all 28 wallpapers live in [`assets/cyberspace-theme/`](assets/cyberspace-theme/).

## Install

```bash
cp -r assets/cyberspace-theme/theme ~/.config/omarchy/themes/cyberspace
omarchy theme set cyberspace
omarchy theme bg cache   # thumbnails for the switcher (Super+Ctrl+Space)
```

The default wallpaper is `00-crab-prince.jpg` (sorts first). All wallpapers
ship inside the theme's own `backgrounds/` folder on purpose — see the gotcha
below about why they must NOT go in `~/.config/omarchy/backgrounds/cyberspace/`.

All wallpapers are pre-cropped/downscaled to ~3200x2000 for the XPS 13's
2560x1600 panel. Fine on the SER8's 3440x1440 too (hyprpaper cover-crops), but
for a pixel-perfect ultrawide set, re-crop from the source links below.
Full-resolution originals of several images are kept in Syncthing under
`~/Sync/omarchy-backgrounds/originals/` (too big for this repo).

## Details worth remembering

- **Muted active border**: `colors.toml` sets
  `hyprland_active_border = "rgba(4ff2f866)"` — the hyprland template reads
  this optional key before falling back to `accent`, so the window border is a
  40%-opacity cyan while the bar/terminal keep the full-neon accent. Last two
  hex digits are the opacity knob.
- **Muted lock screen borders**: `shell.lock.toml` sets `border-alpha = 0.4`,
  one knob the shell applies across the idle/active/error lock borders.
- **Why all wallpapers live in the theme dir, zero-padded**: on theme apply,
  Omarchy looks for the current background in the combined list of
  `~/.config/omarchy/backgrounds/<theme>/` + the theme snapshot — the user
  folder sorts FIRST, so any file there beats the theme's `00-` default when
  Omarchy falls back to "first background" (e.g. switching from another
  theme). Keeping every wallpaper in the theme's `backgrounds/` with
  zero-padded prefixes makes `00-crab-prince.jpg` the deterministic default.
- **Backgrounds added to the theme dir after `theme set` don't show up** in
  the switcher until the theme is re-applied — the switcher reads the snapshot
  in `~/.local/state/omarchy/current/theme/`, not the theme dir. Re-run
  `omarchy theme set cyberspace` after adding files (note: re-applying also
  cycles the wallpaper to the next one; `omarchy theme bg set <path>` to pin).
- **Renaming a theme's first background breaks the theme switcher card**: the
  switcher caches previews as symlinks to the first background file, and its
  staleness check only stats theme-dir mtimes — file renames inside
  `backgrounds/` go unnoticed, leaving a dangling symlink and a missing card.
  Fix: `rm -rf ~/.cache/omarchy/theme-selector && omarchy-theme-switcher --preload`.
- `03-neon-grid.jpg` is generated by
  [`assets/cyberspace-theme/synthwave.py`](assets/cyberspace-theme/synthwave.py)
  (pure-python SVG → `rsvg-convert` → jpg). Edit the palette constants in the
  script to re-render in a different colorway.
- Neovim uses cyberdream, VS Code uses SynthWave '84; both auto-install via the
  theme's `neovim.lua` / `vscode.json`.
